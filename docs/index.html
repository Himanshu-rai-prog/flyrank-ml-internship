Predicting Content Decline for Refresh Prioritization

A transparent baseline and Logistic Regression model for ranking content pages that may require refresh review.

1. Title + Abstract

Question: Can a machine-learning ranking model identify content pages showing signals of decline more effectively than a simple transparent refresh rule?

Data: The working dataset contains 30,000 anonymized content records with search, engagement, content, and lifecycle features.

Method: I compared a transparent rule-based baseline with a Logistic Regression model that ranks pages using predicted probability of decline.

Result: On the ML-08 held-out test split, the model measured Precision@50 of 0.64 versus 0.52 for the baseline, and Precision@100 of 0.66 versus 0.56.

Use: The result is intended as directional decision support for prioritizing pages for human review, not as evidence that every predicted page should automatically be refreshed.

2. Introduction / Problem Statement

Content teams often have more pages that could be reviewed than they can manually inspect. A useful ranking system should therefore help identify which pages deserve attention first while remaining understandable enough for a human reviewer to challenge or override the recommendation.

The specific decision studied here is whether a page should enter a refresh-review queue. The initial baseline deliberately uses a simple lifecycle rule: prioritize pages that are old enough to be considered stale while still receiving meaningful impressions.

The machine-learning question is whether a model using a broader feature set can produce a more useful top-ranked review queue than that transparent rule.

3. Data

30,000 Working records
44 Original columns
34 Model features
32 Clients represented

The analysis uses the anonymized FlyRank internship content-refresh dataset. The working extract contains 30,000 records and includes fields covering content characteristics, search visibility, engagement, lifecycle information, and model/provider metadata.

The dataset includes 90-day activity measures such as impressions, clicks, sessions, and users. It also contains recent and previous 30-day fields. These fields were reviewed carefully because trend-derived information can create target leakage.

Exclusions

  • content_id and client_id were excluded from model features.
  • trend_direction and trend_pct were excluded because the target is derived from trend direction.
  • Recent and previous 30-day trend-related fields were excluded because they directly describe the observed trend used to construct the label.
Public-safety note: This page intentionally does not expose client names, private queries, private URLs, or identifying production information.

4. Methodology

Label definition

The target variable is_declining_label is defined as 1 when trend_direction equals down, and 0 otherwise.

Baseline

The baseline reviews a page when both conditions are satisfied:

  • days_since_last_update ≥ 181
  • impressions_90d ≥ 500

The baseline score is impressions_90d when both conditions are true. Its reason code is stale_but_visible and its action is review_refresh.

Model

The machine-learning model is Logistic Regression. Numerical features are imputed and standardized, while categorical features are imputed and one-hot encoded. The model ranks pages by predicted probability of decline.

Validation design

The validation audit compared a naive random row split with a client-grouped design. The grouped design keeps pages belonging to the same client on only one side of the split, reducing the risk that client-specific patterns are shared between training and testing.

The validation audit used 30,000 records, 34 model features, and 32 clients. The naive row split contained 24,000 training rows and 6,000 test rows.

Leakage checks

Target-derived trend fields were excluded from the feature matrix. Identifiers were also excluded from model features. The leakage audit reported no remaining candidate leakage fields and passed its checks.

Leakage audit: target-derived fields and identifiers were excluded from the model feature matrix.

The model also produced interpretable coefficients. 6. Limitations & Honest Framing

  • The results are measured on this dataset and validation setup; they do not establish identical performance on every future client or dataset.
  • Precision@K evaluates the quality of the top-ranked queue, not whether a refresh will actually improve business performance.
  • A false positive can still be a reasonable human-review candidate. A stale page may be intentionally evergreen or may receive low-quality traffic.
  • Model coefficients represent associations in the training data and should not be treated as causal effects.
  • The baseline is intentionally simple and transparent. Its simplicity makes it useful as a benchmark but also limits the information it can use.

The safest interpretation is therefore: on this dataset and held-out evaluation setup, Logistic Regression measured higher top-of-queue precision than the transparent baseline. This is directional decision support rather than a guarantee of future performance.

7. Ranked Recommendations

  1. Use the model as a prioritization layer. Use the predicted ranking to decide which pages deserve human review first rather than automatically refreshing every selected page.
  2. Keep the transparent baseline as a benchmark. The stale-and-visible rule remains easy to understand and provides a useful reference point for future model iterations.
  3. Review high-ranked pages for context. Check whether the traffic is meaningful and whether the page is intentionally evergreen before recommending a refresh.
  4. Monitor false positives and false negatives. These errors can reveal where the ranking system needs better features, labels, or review rules.
  5. Revalidate before operational use. Future versions should be evaluated on new client or time-separated data before being treated as a production decision rule.
